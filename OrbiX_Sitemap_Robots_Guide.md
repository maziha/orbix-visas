# OrbiX Overseas Careers — sitemap.xml & robots.txt Implementation Guide

**Project:** OrbiX Overseas Careers  
**Website:** orbixvisas.com  
**Framework:** Next.js 13+ (App Router)  
**Prepared:** June 2026

> **For developer use only**

---

## Read this before starting

Both files are created inside the `app/` folder of the Next.js project — not as separate uploads or external files. Next.js automatically generates `robots.txt` and `sitemap.xml` from these files at runtime.

- Do **not** create a static `robots.txt` or `sitemap.xml` in the `public/` folder — they will conflict.
- Do **not** use an external sitemap generator tool — the sitemap will become outdated immediately.

---

## Part 1 — robots.txt

### What it is and why it is required

`robots.txt` is a plain text file that every search engine crawler reads before visiting any page on the website. It tells crawlers which pages they are allowed to visit and which they must skip. It also tells Google exactly where the sitemap is.

For `orbixvisas.com` specifically, `robots.txt` is needed for three reasons:

- Protect internal Next.js file paths (`/_next/`) from being crawled — these are JavaScript bundles, not pages.
- Block API routes (`/api/`) from appearing in Google search results.
- Point Google directly to the sitemap so it always knows where to find the current list of all pages.

### File to create

Create this file at exactly this path in the Next.js project:

```
app/robots.js
```

**Why `.js` and not `.txt`**

In Next.js 13+ App Router, `robots.txt` is generated programmatically from a `robots.js` file inside the `app/` directory. Next.js reads this file at build time and serves the correct plain text `robots.txt` format at `/robots.txt` automatically. Never create a static `.txt` file in the `public/` folder — it will not stay in sync with the site.

### Complete code — paste exactly as written

```js
// app/robots.js
// OrbiX Overseas Careers — orbixvisas.com
// This file generates /robots.txt automatically

export default function robots() {
  return {
    rules: [
      {
        userAgent: '*',
        allow: '/',
        disallow: [
          '/api/',
          '/_next/',
          '/admin/',
          '/dashboard/',
        ],
      },
    ],
    sitemap: 'https://orbixvisas.com/sitemap.xml',
  }
}
```

### What this generates at /robots.txt

When Google visits `https://orbixvisas.com/robots.txt`, it will see:

```
User-agent: *
Allow: /
Disallow: /api/
Disallow: /_next/
Disallow: /admin/
Disallow: /dashboard/
Sitemap: https://orbixvisas.com/sitemap.xml
```

### What each line means

| Line | What it does |
|---|---|
| `User-agent: *` | Applies to all crawlers — Google, Bing, DuckDuckGo, and all others |
| `Allow: /` | The entire website is open to crawl by default |
| `Disallow: /api/` | Blocks Next.js API routes — backend functions, not web pages |
| `Disallow: /_next/` | Blocks Next.js internal file paths — JavaScript bundles, not content |
| `Disallow: /admin/` | Blocks any admin panel. Safe to keep even if one does not exist yet |
| `Disallow: /dashboard/` | Blocks any dashboard route. Safe to keep even if unused |
| `Sitemap: ...` | Tells every crawler exactly where the sitemap file is located |

### ⚠️ Critical — never do this

Never write `Disallow: /` in `robots.txt`. That single line tells Google to not crawl any page on the entire website. It makes the site completely invisible in search results. This is the most common and most damaging `robots.txt` mistake.

## Part 2 — sitemap.xml

### What it is and why it is required

The sitemap is a file that lists every URL on the website that Google should index. Without it, Google discovers pages by following links — which is slower, less complete, and gives no control over which pages get crawled first. Submitting a sitemap in Google Search Console is the fastest way to get a new website indexed.

The sitemap for `orbixvisas.com` must be auto-generated by the Next.js application — not created as a static XML file or generated by a third-party tool. A static or external sitemap will become outdated the moment any page is added or removed from the site.

### File to create

Create this file at exactly this path in the Next.js project:

```
app/sitemap.js
```

### Complete code — all current orbixvisas.com URLs included

Paste this file exactly as written. All current pages are included. When a new page is added to the site in future, add its URL to the `routes` array and the sitemap updates automatically.

```js
// app/sitemap.js
// OrbiX Overseas Careers — orbixvisas.com
// This file auto-generates /sitemap.xml
// To add a new page: add a new object to the routes array below

export default function sitemap() {
  const baseUrl = 'https://orbixvisas.com'

  const routes = [

    {
      url: '/',
      priority: 1.0,
      changeFrequency: 'weekly',

    {

      priority: 0.9,
      changeFrequency: 'weekly',
    },

    // ── STUDY ABROAD ─────────────────────────────────────
    {
      url: '/study-abroad',
      priority: 0.8,
      changeFrequency: 'weekly',
    },
    {
      url: '/study-abroad/canada',
      priority: 0.8,
      changeFrequency: 'monthly',
    },
    {
      url: '/study-abroad/australia',
      priority: 0.8,
      changeFrequency: 'monthly',
    },
    {
      url: '/study-abroad/uk',
      priority: 0.8,
      changeFrequency: 'monthly',
    },
    {
      url: '/study-abroad/germany',
      priority: 0.8,
      changeFrequency: 'monthly',
    },
    {
      url: '/study-abroad/new-zealand',
      priority: 0.7,
      changeFrequency: 'monthly',
    },
    {
      url: '/study-abroad/france',

    },
    {
      url: '/study-abroad/poland',
      priority: 0.7,

    },

    // ── VISA SERVICES ────────────────────────────────────
    {
      url: '/services',
      priority: 0.8,
      changeFrequency: 'monthly',
    },
    {
      url: '/services/spouse-visa',
      priority: 0.8,
      changeFrequency: 'monthly',
    },

      url: '/services/parent-visa',

      changeFrequency: 'monthly',
    },
    {
      url: '/contact',
      priority: 0.8,
      changeFrequency: 'monthly',
    },
  ]

  return routes.map(route => ({
    url: `${baseUrl}${route.url}`,
    lastModified: new Date().toISOString(),
    changeFrequency: route.changeFrequency,
    priority: route.priority,
  }))
}
```

### Priority values explained

The `priority` field tells Google the relative importance of pages within the site. It is a scale from `0.1` to `1.0`. Pages with the same priority are treated equally.

| Priority | Pages assigned this value | Reasoning |
|---|---|---|
| 1.0 | Homepage (`/`) | Entry point — most important page on the site |
| 0.9 | Migration index, Canada PR, Australia PR | Primary commercial pages — highest business value |
| 0.8 | Study abroad index, country pages, services, contact | Important service pages — high conversion value |
| 0.7 | Lower-traffic study destinations, student dependent visa | Secondary service pages — relevant but less searched |
| 0.5 | About page | Informational — important for trust but low search intent |

## Part 3 — How to add a new page to the sitemap

Every time a new page is added to the website, add one new object to the `routes` array inside `app/sitemap.js`. Do not regenerate the sitemap manually or use an external tool. The file handles everything automatically.

### Example — adding a new blog page

If a blog section is added at `/blog` and the first article is at `/blog/canada-express-entry-guide`, add these two objects to the `routes` array:

```js
// Add inside the routes array in app/sitemap.js
{
  url: '/blog',
  priority: 0.7,
  changeFrequency: 'weekly',
},
{
  url: '/blog/canada-express-entry-guide',
  priority: 0.6,
  changeFrequency: 'monthly',
},
```

### Example — adding a new city landing page

```js
// Add inside the routes array in app/sitemap.js
{
  url: '/immigration-consultant-ernakulam',
  priority: 0.8,
  changeFrequency: 'monthly',
},
```

### Rule of thumb for priority values

- **Service pages and pages that drive consultations:** 0.8–0.9
- **Blog articles and informational content:** 0.5–0.7
- **Utility pages (about, privacy policy, terms):** 0.3–0.5
- Never set anything higher than `1.0` or lower than `0.1`

## Part 4 — Verification steps

After deploying both files, complete every step below in order. Do not submit to Search Console until all checks pass.

### Step 1 — Verify robots.txt is live

Go to `https://orbixvisas.com/robots.txt` — you should see plain text with the rules listed.

If you see a 404 error, the `app/robots.js` file was not deployed correctly or is in the wrong folder.

### Step 2 — Verify sitemap.xml is live

Go to `https://orbixvisas.com/sitemap.xml` — you should see a structured XML file listing all URLs.

If you see a 404 error, the `app/sitemap.js` file was not deployed correctly. Count the entries — there should be **18 URLs** matching the routes in the file.

### Step 3 — Validate the sitemap format

Go to `https://www.xml-sitemaps.com/validate-xml-sitemap.html` and paste the sitemap URL. Alternatively use Google Search Console — it validates the sitemap automatically when you submit it. Fix any errors before submitting.

### Step 4 — Submit to Google Search Console

Log into Google Search Console (`search.google.com/search-console`). Select the `orbixvisas.com` property. Click **Sitemaps** in the left menu. Enter the sitemap URL: `https://orbixvisas.com/sitemap.xml` and click **Submit**. Google will begin crawling all listed pages within 24–48 hours.

### Step 5 — Test robots.txt in Search Console

In Search Console, go to **Settings** in the bottom left. Click **robots.txt** under Crawling. The tester shows whether Google can read the file and lets you test specific URLs to confirm they are allowed or blocked.

## Part 5 — Ongoing maintenance

Once both files are deployed and verified, ongoing maintenance is minimal.

| When this happens | What to update |
|---|---|
| A new page is added to the site | Add a new object to the `routes` array in `app/sitemap.js`. Deploy. The sitemap updates automatically — no resubmission to Search Console needed. |
| A page is permanently removed | Remove its object from the `routes` array in `app/sitemap.js`. Set up a 301 redirect from the old URL to the most relevant remaining page. Deploy. |
| A new admin or backend route is added | Add it to the `disallow` list in `app/robots.js` if it should not be indexed. Example: add `'/new-admin-route/'` to the disallow array. |
| The domain name changes | Update the `baseUrl` constant in `app/sitemap.js` and the sitemap URL in `app/robots.js`. Update the canonical tags, OG image URLs, and Google Business Profile simultaneously. Resubmit the sitemap in Search Console. |
| A blog section is added | For static blog posts, add each post URL to the `routes` array manually. For a database-driven blog, update `sitemap.js` to query the database and return all published post URLs dynamically — this requires a code change to the sitemap function. |
